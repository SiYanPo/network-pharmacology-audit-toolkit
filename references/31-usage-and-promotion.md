# 31 · 高专业度用户使用规范与推广建议

> 面向：PI、博后、研究生、跨学科合作者。目的不是"教会点按钮"，而是**防止误用**——
> 这个工具最容易造成的伤害不是算错，而是让人把"计算假说"当成"实验结论"。

---

## 1 四类用户，四个入口

| 角色 | 需要什么 | 入口 | 不该做什么 |
|---|---|---|---|
| **PI / 通讯作者** | 结论可信度、可投稿性 | 报告首页的**门禁看板** + `benchmark_report.md` | 不要只看 AUC 与通路图下结论 |
| **博后 / 方法学负责人** | 参数、对照、复现 | `np_pipeline` + `np_finalcheck` + `np_selfaudit` | 不要手改 `np_out` 里的 CSV 再出报告 |
| **研究生（执行）** | 一步步跑通 | `streamlit run app.py` | 不要跳过 `np_preflight` 与禁忌检查 |
| **合作者（湿实验）** | 做哪个靶点、用什么引物 | 报告第 8 节（同源）+ `np_lab`/`np_primer` | 不要把 `(FuncRep)` 当直系同源 |

---

## 2 标准作业流程（SOP）

### 阶段 0：立项前（30 分钟，决定这事值不值得做）
1. `np_preflight.py`：环境不过关不要开始。
2. 明确**病症与组织**（HPA 背景需要）、**方剂与药味**（含炮制）、**候选靶点数上限**。
3. 先读 `benchmark_report.md`：同类方剂的 AUC/EF 大致什么水平——预期管理比事后解释重要。

### 阶段 1：数据准备（最容易出错的地方）
| 输入 | 硬性要求 | 常见错误 |
|---|---|---|
| 成分表 | 每行一个成分，含 OB/DL/MW/herb | 把复方成品当"成分" |
| 成分-靶点边 | 蛋白名或基因符号**统一一种** | 混用 TCMSP 蛋白全名与 HGNC 符号 |
| 疾病靶点 | gene,score,source 三列 | 把通路名当基因 |
| PPI 边 | node1,node2,weight | 用无 score 的两列表 |
| GMT | 制表符分隔，≥3 基因/条目 | 用 KEGG 网页复制的空格分隔文本 |
| 方向表（可选） | gene,direction | 用"上调/下调"以外的自由文本 |

> 基因符号必须 ≥2 字符（`read_gene_list` 会过滤单字符 token，这是刻意设计，不是 bug）。

### 阶段 2：运行
```bash
python scripts/np_pipeline.py --inputs inputs.json -o np_out --enable-funnel
python scripts/np_finalcheck.py --dir np_out --auto-fix --tissue <组织>
python scripts/np_uireport.py --dir np_out --label "方剂-疾病" --verdict DRAFT --pdf
```

### 阶段 3：复核（**不可跳过**）
按顺序看四件事，任何一项不过就不进入写作：
1. **门禁看板**：硬性项必须全过；未过的逐条看修复命令。
2. **零模型**（第 6 节）：Z 值是否显著？不显著说明你的网络和随机网络没差别。
3. **富集背景**（第 7 节）：是否 HPA/DEG？"P-value may be inflated"是否亮红？
4. **方向一致性**（第 9 节）：有 MR 时，红灯靶点**不得**作为主结论。

### 阶段 4：写作
- 结论措辞按证据级别（L1 假说 / L2 结构支持 / L3 体外 / L4 体内），`np_evidence` 可机检。
- 方法段直接引用 `benchmark_report.md` 的 Methods 段 + `Data Provenance` 表。
- 所有数字必须能追溯到 `np_out` 里的文件；报告不允许人工改数。

## 3 参数默认值与何时改

| 参数 | 默认 | 何时必须改 | 改了要写进 Methods |
|---|---|---|---|
| `--min-score`（PPI） | 0.4 | 高置信网络用 0.7；覆盖不足用 0.15 | 是 |
| `--top`（hub） | 15 | 靶点数 >200 时 20–30 | 是 |
| `--expand-min-degree` | 3 | 想让 degree=3 的也扩展 → 4 | 是 |
| `--background-mode` | auto（HPA） | 有 DEGs 时用 `deg` | 是（含组织名） |
| `--q`（富集） | 0.05 | 探索期 0.1，投稿 0.05 | 是 |
| `--calibrate` | 0（关） | 投稿前至少 1000 次 | 是 |
| `--clump-r2` / `--clump-kb` | 0.001 / 10000 | 无 LD 面板时只能距离剪枝，**必须标注** | 是 |
| `--drug-direction` | 无 | 有任何"药物激活/抑制"主张时必须给 | 是 |

## 4 十种高频误用（按危害排序）

1. **把交集靶点当"有效靶点"**：交集只说明"成分能碰到 + 疾病相关"，不说明有效。
2. **忽略零模型**：不显著还写"核心模块"。
3. **全基因组背景 + 小 q 值**：最容易被拒稿的统计学问题。
4. **hub 排序换着用**：原始网络与扩展子网的 degree 不可混用。
5. **把 FuncRep 当直系同源**：PCR 必失败（已由 G22 拦截）。
6. **对接打分当亲和力**：Vina 分数不是 Kd，且未做重对接门禁的对接不可报。
7. **MR 方向不看**：靶点升高保护疾病，成分却抑制 → 结论反了。
8. **一个方剂跑通就宣称"平台有效"**：没有 benchmark 的软件文章会被拒。
9. **报告里手改数字**：一旦被要求提供原始产物就穿帮。
10. **不记录数据库版本/日期**：审稿人要求复现时无法回答。

## 5 教学方案（2 小时工作坊）

| 时长 | 内容 | 产出 |
|---|---|---|
| 15 min | 为什么 NP 论文难复现：三个真实翻车案例 | 认知对齐 |
| 20 min | 环境与数据契约：preflight + 五张表 | 每人跑通 preflight |
| 30 min | 一键流程 + 读报告（看板/零模型/富集背景） | 每人出一份报告 |
| 20 min | 参数敏感性：改 min-score/q 看结论是否翻转 | 一张敏感性表 |
| 20 min | 因果层：MR/COLOC 的正确措辞与方向校验 | 一段可用的 Discussion |
| 15 min | 审稿人 20 问速答（assets/reviewer_qa.md） | — |

**考核标准**：能独立解释"为什么这个 hub 不是结论"、"P 值为什么可能膨胀"、"FuncRep 为什么不能做引物"。

## 6 推广策略（学术场景，不做营销）

### 6.1 对内（课题组）
- **统一入口**：只推 `streamlit run app.py` 与 `np_pipeline` 两条命令，其余脚本按需。
- **统一产物目录**：`runs/<日期>_<方剂>_<疾病>/`，禁止各自为政。
- **每周一次"报告会诊"**：拿一份 DRAFT 报告，集体找"哪一句没有证据"。

### 6.2 对外（合作者/同行）
- **给三样东西**：`PORTABILITY.md` + `snapshot_*.tar.gz` + 一份带 DRAFT 水印的示例报告。
- **不给源码压缩包就完事**：必须附"最小复现命令"与"预期运行时间/产物体积"。
- **版本固定**：合作论文引用 commit hash（如 `v2.9.0@a1b2c3d`），不用"最新版"。

### 6.3 学术产出
- 软件论文（GigaScience / Bioinformatics Apps）优先于"再发一篇 NP 案例"。
- 把 benchmark 与失败案例整理成 **resource paper**（数据+基准本身可引用）。
- 在 Methods 里给出"可复现声明"：快照哈希、CI 链接、运行时长、随机种子。

### 6.4 支持流程（避免变成免费客服）
1. 提问模板：版本 + 命令 + 报错末 20 行 + `np_preflight --json` 输出。
2. 只修"可复现的 bug"；参数选择类问题给文档链接，不代跑。
3. 每月合并一次社区 issue，进 CHANGELOG。

## 7 每次交付前必查（5 条）

- [ ] `np_preflight` 无 FAIL
- [ ] 门禁硬性项全过（或明确写出为什么不过）
- [ ] 零模型显著、富集背景非全基因组（或有红框警告）
- [ ] 所有图/表能在 `np_out` 里找到源文件
- [ ] 报告里的每个数字都能用一条命令重算
