# 实战踩坑清单（37 条）

> 来源：一线审稿意见、中文社区实操帖（CSDN/公众号/知乎）、开源项目 issue、以及方法学文献。
> 每条给「现象 → 原因 → 处理」，可直接当排错手册用。

## A. 数据获取（1–9）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | TCMSP 抓取突然全部 404 | 页面 `token` 会变，硬编码 token 失效 | 每次会话重新取 token；脚本失败时回退到"手动导出 + 本地读表" |
| 2 | 抓几十味药后 IP 被封 10 分钟 | 并发过高（20 线程实测即触发） | 单线程 + 0.5–0.8 s 随机延时；断点续抓，不要重头跑 |
| 3 | 成分表列名对不上，解析全空 | 页面结构改版 | 解析后先断言必需列（MOL_ID/OB/DL），缺列立即报错而不是静默产出空表 |
| 4 | 中文乱码 | TCMSP 有时 UTF-8、有时 GBK | 按 `utf-8-sig → utf-8 → gb18030` 顺序试解，`npcore.read_table` 已实现 |
| 5 | UniProt VLOOKUP 大量 #N/A | protein_name 含括号别名、亚型（-alpha/-beta）、多别名 | 用四层匹配（精确→规范化→结构拆解→别名表），不要指望 Excel 精确匹配 |
| 6 | `Lysozyme` 被映射到 `LYZL6` | 宽松匹配取第一个命中 | 前缀命中优先 + 名称最短优先；reviewed 无果才查全库；把易错项写进修正表且**修正表优先于缓存** |
| 7 | 缓存一直返回旧的错映射 | 缓存覆盖了人工修正 | 加载顺序：修正表 > 缓存 > 在线查询 |
| 8 | 疾病靶点一搜几千个，全当"疾病相关" | 未设阈值、未分来源 | 记录阈值与版本；按来源分层（遗传/审编/整合/表达） |
| 9 | GeneCards 对脚本 403 | 反爬 | 手动导出 CSV；或改用 Open Targets / CTD 作为主源 |

## B. 标准化与交集（10–15）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 10 | 交集为零 | 一侧是蛋白名、一侧是符号 | 先跑 `np_standardize.py`，再取交集 |
| 11 | 交集很少（<5） | 成分被 OB/DL 筛太狠、或疾病集取得太窄 | 见 `intersect_report.md` 六步恢复序列；不要靠换阈值硬凑 |
| 12 | 同一蛋白在表里出现两次 | 同物异名（Prothrombin / F2） | 标准化后再去重；`np_standardize` 输出 layer 列便于审计 |
| 13 | 靶点里混入细菌/病毒蛋白 | TCMSP 含 `Cytochrome P450-cam`、`Rhinovirus coat protein` 等 | 非人类条目单列剔除（不要强行映射到人类基因） |
| 14 | 靶点里有 `mRNA of ...` | TCMSP 历史噪音条目 | 归入 noise 类剔除 |
| 15 | 映射率 60% 却直接往下做 | 未看审计 | 映射率 <80% 必须先补别名表，否则交集被系统性稀释 |

## C. PPI 与 hub（16–22）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 16 | 网络密度 >1 | 自环 + 重复边未清理 | 合并重复边、剔除自环（本平台自动计数并报告） |
| 17 | STRING 基因名变成 `9606.ENSP...` | API 返回 stringId | 取 `preferredName` 列；或按 `9606.` 前缀过滤 |
| 18 | `get_string_ids` 返回空字典 | 首列是 `queryIndex` 而不是 `queryItem` | 按序号回索引输入列表 |
| 19 | MCODE 把整个网络吞成一个模块 | MCODE 在稠密小网络上退化 | 默认用 Louvain（互斥划分）；MCODE 需设模块规模上限 + 模块间去重 |
| 20 | Degree 最大的基因被叫"核心靶点" | 度≠重要性 | 多指标共识 + bootstrap 入选频率 + 度匹配零模型 |
| 21 | 换一批边（同阈值重下）hub 全变 | 未做稳健性 | 报入选频率；<0.60 只能写"度排序前列节点" |
| 22 | 网络图糊成毛线球 | 节点过多 | 分层出图：药材-成分、成分-靶点、靶点-靶点各一张；或按度保留 top 50 并声明 |

## D. 富集（23–28）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 23 | Enrichr 返回 400 后 429 | 该服务限流严重、不稳定 | 改用 g:Profiler（一次拿 GO/KEGG/REAC/WP，自带 FDR）或本地 GMT |
| 24 | 富集"全部显著" | 背景取错（用输入集自身当背景）或疾病集过小 | 明确 N 与 K 的来源；提供 `--background` 实测背景 |
| 25 | 同一通路重复出现两行 | 不同 source 同名条目 | 按 `(source, name)` 去重 |
| 26 | 200 条 GO 条目当 200 个机制 | 未折叠冗余 | Jaccard ≥0.5 折叠，报告折叠前后数量 |
| 27 | "Pathways in cancer" 被当机制结论 | 伞状通路命中门槛极低 | 三层分级；伞状/感染类单列，不作结论 |
| 28 | P 值被当"作用强度" | 概念混淆 | P 只表显著性；效应看倍数富集与命中数 |

## E. 对接与 MD（29–33）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 29 | 对接打分正数 | 受体/配体格式错、盒子位置错 | 先看盒子是否覆盖口袋；检查 PDBQT 原子类型 |
| 30 | 重对接 RMSD 3 Å 还想解释 | 口袋定义/质子化错 | 门禁：>2 Å 该靶点结果作废，回查受体与口袋 |
| 31 | 只对接 3 个成分，却称"验证了整个网络" | 选择性报告 | 说明选择依据；对接是 L2 证据，不是验证 |
| 32 | MM-GBSA 数值与文献差一个量级 | 简化模型（单轨迹、通用 GB）不可跨研究比较 | 只用于同靶点内相对排序，并在方法学声明 |
| 33 | OpenCL 平台加位置限制力后轨迹 NaN | 某平台对 CustomExternalForce 实现缺陷 | 平衡段固定 CPU，生产段再切 GPU；切换平台须重建 integrator |

## F. 工程与复现（38–45，v1.1 新增）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 38 | 同一数据两次运行，hub 排序略有不同 | 排序并列时依赖 `set`/`dict` 迭代顺序，受 `PYTHONHASHSEED` 影响 | 所有按值排序必须带**次级键**（节点名）；已修，并有回归测试 |
| 39 | 写 CSV 时报 `OverflowError: cannot convert float infinity` | `fold`/`z` 在期望为 0 或方差为 0 时为正/负无穷 | `_fmt_cell` 显式处理 ±inf 与 NaN；已修 |
| 40 | 用 `x or default` 判断 0.0 导致错误分支 | 0.0 是合法值（完美匹配），被当成"缺失" | 一律写成 `x is None` 判断；已在零模型校准处修复 |
| 41 | 审计器对"本文不把 P 当作用强度"报警 | 散文正则会命中否定句 | 加否定窗口检测；并把措辞类规则降为"提示"，不计入评分 |
| 42 | 报告里的方法学参数与用户设置不一致 | 参数从错误的阶段读取，缺失时用默认值兜底 | 参数必须带来源阶段；缺失标"未记录"，禁止默认值兜底 |
| 43 | 审计"存在账本"永远 FAIL | 账本生成在审计之后（顺序依赖） | 编排器在审计前统一生成 `claims.json` |
| 44 | 换机器后结果对不上 | 只有 Python 版本，没有包版本/locale/命令行 | `environment.json` + `reproduce.cmd/.sh` + `evals/repro_check.py` |
| 45 | 大文件哈希相同但内容不同 | 只哈希前 8 MB 且未标注 | 改为全量哈希；如需截断必须写 `partial: true` |

## 一句话总结

绝大多数"网络药理学被质疑"，不是算错了，而是**没说清数据从哪来、为什么这么算、结果最多能说明什么**。
本平台的 11 个阶段与 26 条审计规则，本质就是把这三句话变成可执行检查。

## H. 真实数据运行暴露的坑（v1.2，48 化合物 × 2 型糖尿病）

这一节全部来自一次真实运行，不是设想。共同特征是：**不报错，但结果是错的**。

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 46 | 类药性门控把阿托伐他汀（QED 0.16）、二甲双胍（0.25）、地高辛（0.16）、哇巴因（0.14）判为不合格 | QED/Veber 描述**理化性质空间**，与药效无关 | 用 `--gate evidence`；若必须用类药性，把已上市药物列入 `--exceptions` 并在局限性说明 |
| 47 | 中文路径下 RDKit 报 `OSError: Bad input file`，报错不提及编码 | RDKit 用 C++ 流打开文件，不认 UTF-8 路径 | 读写改为文本 + `MolFromMolBlock`；中间产物放 ASCII scratch 目录 |
| 48 | STRING 边权全为 0 | 当前 API 的 `score` 是 0–1 浮点，旧文档写 0–1000；`int()` 后归零 | 保留浮点；仅当 >1 时按 1000 缩放 |
| 49 | Open Targets 查旧 EFO 号返回空，无任何错误 | 主键已迁至 MONDO，旧 ID 返回 `null` | 用 MONDO 号；抓取后显式断言 `data.disease is not None` |
| 50 | `bc_excess_z` 全为 0，「没有桥接节点」 | 「度±1」窄窗里同伴不足 → 标准差无定义 | 等频分箱；NA 与 0 分开输出 |
| 51 | 经验 P 大量并列在 0.00498 | 那是 `1/(B+1)` 的下限（B=200） | 报告写出下限；需要区分时把 B 提到 ≥1000 |
| 52 | 蛋白名词典缺 `15-hydroxyprostaglandin dehydrogenase [NAD(+)]` | 取推荐名时按 `(` 切分，方括号内的括号被当成别名起点 | 按括号深度切分；词典改用 UniProt 全量 |
| 53 | `--gmt a.gmt,b.gmt` 被判「文件不存在」 | 预检把整串当单路径 | 预检按逗号拆分 |
| 54 | 同一份数据，两次运行交集基因数不同（70 vs 69） | 两次运行之间改过词典，映射结果变了 | **改动词典/别名表必须重跑并记录版本**；`run_manifest.json` 的输入哈希可定位 |
| 55 | PubChem 按 CID 取 `CanonicalSMILES` 返回 `None`，RDKit 解析报 `Bad input file` | PUG REST 的 `CanonicalSMILES` / `IsomericSMILES` 对部分 CID（如黄芪甲苷 CID 13943297）为空，实际有 `SMILES` / `ConnectivitySMILES` | 属性依次尝试 `SMILES,ConnectivitySMILES,CanonicalSMILES`，取首个非空；空值不要让下游静默通过 |
| 56 | 同一个通路命中数不变，换个背景 N，P 从 2e-16 变到 6e-9 | 超几何 P 强依赖背景 N；默认 20596 与实测检出空间不是一回事 | 报背景来源；有表达谱用实测背景，无则标"探索性"；在讨论里做背景敏感性说明（真实数据见 `04-statistics.md` §1.1.1） |

### 一条可复用的判据

> 凡是"改了环境/改成中文路径/换了数据源就悄悄变结果"的环节，
> 都不该只在论文里写"使用默认参数"，而要把**版本、路径、哈希**写进溯源。
> 上表 47–49 三条，任何一条都足以让"可复现"变成不可能，而且不会有人报错给你。
