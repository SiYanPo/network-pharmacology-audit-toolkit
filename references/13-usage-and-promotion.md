# 面向高专业度用户的使用规范与推广方案

> 目标读者：课题组 PI、博士后、方法学审稿人、研究生。
> 本文回答三个问题：**怎么用才不出错**、**怎么教别人不出错**、**怎么判断别人用错了**。

---

## 一、五条使用纪律（违反任何一条，结果不可用于投稿）

### 1. 先自检，再分析

```bash
python scripts/np_doctor.py
```

数据源不可达 ≠ 生物学阴性。若 STRING/g:Profiler 不可达，报告必须写"数据源不可用"，
**不得**写成"未富集到该通路"。脚本已按此实现，但作者仍需在正文体现。

### 2. 参数永远显式，不依赖默认值

```bash
python scripts/np_run.py ... --dry-run    # 先看生效参数
```

默认值是"最常用且可辩护"，不是"适用于你的数据"。v1.1 起，报告会列出**参数来源核对表**；
出现「未记录」必须补齐阶段后重跑，**不得**手改报告文字。

### 3. 审计 FAIL 视为阻断，WARN 逐条书面确认

```bash
python scripts/np_audit.py --dir out/ --strict
```

- **结构性规则（18 条）**计分，代表"该有的东西有没有"。
- **提示性规则（11 条）**不计分，是散文启发式，可能误报；命中后人工判断，不要机械修改。
- 习惯：把 WARN 的处理方式写进项目 README（"为何接受此 WARN"），比争论更有用。

### 4. 引用必须能点开

`references/12-methods-bank.tsv` 中：
- 标"已核验"的可直接引；
- 标"须自行复核"的**不得**直接引；
- 引用时**引原始文献**，不要只引本技能。

### 5. 措辞受证据约束

L1 结果只能写"提示/支持"；L2 写"预测/结合模式提示"；L3 才能写"表明"；L4 才能写"证明"。
这不是文风建议，是审稿人最先检查的一项。

## 二、三种典型工作流

### A. 开题/预实验（1–2 周，Lite 档）

```bash
# 1. 只跑必要阶段
python scripts/np_run.py --targets t.csv --compounds c.csv --disease d.tsv \
    --edges s.tsv --gmt p.gmt --stages 01,02,03,04,05,06 -o lite/

# 2. 看三件事
#    - 交集是否 ≥5（不足 → 改设计，别硬做）
#    - C 组零模型是否通过校准（否则机制表述降级）
#    - 泛成分占比（>50% → 换非泛成分做敏感性分析）
```

产出用于：判断"这个题值不值得做"，而不是发文章。

### B. 正式研究（3–5 周，Standard 档）

全流程 + `--calibrate 500`（富集经验校准）+ `--bootstrap 500`（hub 稳健性）。
交付三件套：`np_report.html` + `run_manifest.json` + `environment.json`。

### C. 投稿前终检（半天）

```bash
python scripts/np_audit.py --dir out/ --strict        # 结构性 FAIL 必须为 0
python evals/repro_check.py --a out/ --b out_rerun/   # 重跑一次，确认可复现
```

再人工过一遍 `claims.json`：每条结论的 `source` 文件是否存在、数值是否一致。

## 三、教学方案（面向研究生，3 次课）

| 次 | 主题 | 现场演示 | 作业 |
|---|---|---|---|
| 1 | 网络药理学能说什么、不能说什么 | `--demo` 跑一遍，读审计报告 | 找出自己领域一篇论文的 3 个可质疑点 |
| 2 | 对照：为什么"连接紧密"不算证据 | 现场改 `np_null` 的匹配方式，看零均值从 46 变 120 | 用自己数据跑 C 组，解释校准表 |
| 3 | 暴露：体外浓度能不能到体内 | `np_dose` 反推所需剂量 | 给自己关心的成分算一遍 |

**教学金句**（可直接用）：
> "同一份数据，换个背景，P 从 1e-40 变成 0.35。你要报告哪一个？为什么？"

这比讲十遍公式有效。

## 四、推广方案

### 4.1 面向课题组（低成本、高转化）

| 动作 | 成本 | 效果 |
|---|---|---|
| 组会 20 分钟 demo（只演 `--demo` + 审计 FAIL 怎么读） | 1 小时准备 | 立刻有人用 |
| 提供"开题检查表"（`references/03` 的 Lite 清单打印版） | 零 | 形成习惯 |
| 建立组内 `templates/` 目录，预置 `--route`、阈值约定 | 半天 | 减少重复讨论 |
| 指定一名"方法学守门人"，负责投稿前跑 `--strict` | 每周 1 小时 | 质量下限有保障 |

### 4.2 面向同行（学术传播）

1. **方法学短文**：本技能的 29 条规则可直接改写为"网络药理学报告清单（NP-RC）"。
   目前该领域尚无公认 reporting checklist，这是最容易占领的位置。
2. **教学案例**：把"双背景翻转结论""零模型未校准导致效应虚高 3 倍"写成两个 box，
   可作为方法学论文的 Figure 1。
3. **开源与引用**：MIT 许可，建议在论文方法学中写"分析流程基于 network-pharmacology-pro v1.1
   （附 commit 与参数快照）"，而不是只写软件名。

### 4.3 面向审稿（反向推广）

审稿时用同一套规则检查别人的稿子：
- 有没有零模型？（R13）
- 富集背景写了吗？（R12）
- hub 给入选频率了吗？（R15）
- 剂量核算有吗？（R25）

四条里缺两条以上，基本可以判断"计算堆砌、无对照"。这套话术比"我觉得不够严谨"有力得多。

### 4.4 推广时必须说明的三条边界

1. **不能替代实验**：全部产出为 L1–L2。
2. **不适用于非人类物种**（词典与 PPI 默认 9600/9606 人类）。
3. **词典覆盖有限**（约 320 条），冷门靶点需人工补 `--alias`。

> 主动说边界，比等人来质疑更建立信誉。

## 五、常见误用与纠正

| 误用 | 症状 | 纠正 |
|---|---|---|
| 把审计分当"论文质量分" | "我 100 分，可以投了" | 审计只查可辩护性，不查科学价值；PASS ≠ 结论正确 |
| 用 `--force` 绕过途径门禁后忘记声明 | 方法学里写"按口服筛选"但实际是注射剂 | `--force` 会写警告进 manifest，投稿前搜一遍 warnings |
| 把 `claims.json` 当结论清单直接抄进摘要 | 摘要出现"43 个靶点"却无机制表述 | 账本给数值，机制表述仍需作者按证据等级写 |
| 用默认背景跑富集后写"显著富集" | 审稿人问"背景是什么" | 报告已标"探索性"，正文须同步标注 |
| 只跑 04/06 两个阶段就写全流程 | manifest 只有 2 个阶段，R03 WARN | 补跑上游或明确写"仅做拓扑与富集分析" |

## 六、版本与维护约定

- **语义化版本**：修复缺陷 → patch；新增阶段/规则 → minor；改变默认参数或输出契约 → major。
- **不兼容变更**必须写进 `CHANGELOG.md`，并在 `SKILL.md` 顶部保留"关键变更"表。
- **规则只增不删**：审计规则编号（R01–R29）永久保留，废弃的标 `deprecated` 而不复用编号。
- **回归优先**：任何缺陷修复必须同时在 `evals/regression.py` 增加一条会变红的断言。

> 最后一条是本项目最重要的工程约定：**没有回归测试的修复，等于没修**。

## 6. 门控怎么选：三种尺子，三种问题（v1.2 新增，最容易用错的地方）

很多人把"筛成分"当成一道工序，其实它是三个不同的问题，对应三把尺子：

| 门控 | 回答的问题 | 适用对象 | 会误伤谁 |
|---|---|---|---|
| `obdl`（OB≥30, DL≥0.18） | 「口服后能不能达到有效暴露」的**粗代理** | 中药饮片来源成分 | **苷类、皂苷、多糖、挥发油**（几乎必然被判不合格，但不等于无活性） |
| `druglike`（QED + Veber） | 「像不像口服小分子药」 | 合成物、单体筛选 | **已上市的大分子量/高极性药**：阿托伐他汀、二甲双胍、地高辛、哇巴因 |
| `evidence` | 「有没有实测活性/入血证据」 | 已上市药物、阳性对照、单体 | 不误伤，但要求你能拿出证据；不能用来"过滤掉不想讨论的成分" |

### 现场判断流程

1. 队列里**有已上市药物**（阳性对照、老药新用、联合用药）→ 必须用 `--gate evidence`，
   或把药物逐个列入 `--exceptions` 并在方法学说明。
2. 队列**全部是中药饮片成分**，且手上有 TCMSP 导出的 OB/DL → 用 `obdl`，
   并用 `--obdl-snapshot` 把来源文件固化（哈希写入 manifest）。
3. 队列**全部是合成单体/候选化合物**，无 OB/DL → 用 `druglike`，
   但必须同时报「被剔除的已上市对照」——如果对照组被剔了，这个分析已经失去校准锚点。
4. 无论哪种，**都要报剔除清单与理由**，并做一次「放宽门控」的敏感性分析
   （本技能实测：31 个 vs 47 个成分，交集基因 69 个、top-5 hub 完全不变 → 结论对门控稳健）。

> 一句话：门控是**设计选择**，不是**质量判据**。把门控当质量判据，审稿人一句
> 「你们把阿托伐他汀筛掉了」就能否掉整段结果。

## 7. 真实对接怎么跑（08a）

```bash
# 1) 先只做重对接校验：证明这套协议在你的靶点上能复原晶体姿态
python scripts/np_dockprep.py --plan plan.tsv --outdir dock/ --validate-only --vina /path/vina

# 2) 看 docking_validation.csv：RMSD ≤2 Å 的靶点才允许出分
# 3) 只对通过校验的受体重跑跨对接（--reuse-validation 省掉重复校验）
python scripts/np_dockprep.py --plan plan.tsv --ligands compounds.csv --outdir dock/ \
    --reuse-validation --max-compounds 14
```

**plan.tsv 格式**（`ligand_code` 写 `AUTO` 让程序自动挑共晶配体）：

```
target	pdb	ligand_code	chains
HMGCR	1hwk	AUTO	A
PPARG	2prg	AUTO	A
```

**必须写进论文的三件事**：
1. 每个靶点的重对接 RMSD（不是"平均 1.5 Å"，而是逐靶点）；
2. 未通过校验的靶点及其处置（本技能实测 DPP4 3.06 Å → 不出分）；
3. 盒子的中心与边长（`docking_validation.csv` 的 `box` / `box_size` 列已记录）。

> 只报"结合能 −8.9 kcal/mol，结合稳定"而不报重对接 RMSD，是当前对接类论文最常见的硬伤：
> 读者无法判断这个分数是"算得准"还是"算得动"。
